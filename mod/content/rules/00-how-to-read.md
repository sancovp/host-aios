# HOW TO READ — Read reads, Write and Edit change, Bash finds

TRIGGER:[looking inside a file · searching for a file or a line · changing a file · entering a folder to work in it]

DO:[
- use Bash and the search tools to find which files matter and how they are laid out, and Read to read a file's
  contents; a folder's CLAUDE.md, rules and skills load only when Read, Write or Edit touches a file in it
- change files with Write and Edit
- peek at a file only while searching, when you do not yet know whether it matters
- when the work needs a file that is not already in context — the design you work under, the code you will change —
  read all of it with Read, a file too long for one call in consecutive chunks, each starting where the last ended;
  wanting to peek at a file you are not searching for means you already need it
- when the request, a read list or a goal's table names a file, you are not searching for it: read it whole with Read,
  in consecutive chunks where it is long
- change a document only with Write or Edit, because only Read, Write and Edit load a folder's CLAUDE.md and rules, and
  only Write and Edit are seen by the guards that check a write and a turn's end
- judge prose and a design by reading them, and their structure by the canonical gates — the read-order check, the
  state-file gate and the goal checker — since only a reader can tell whether a text says what it should
- when you enter a folder to work in it, first learn its layout — what it holds, and the rules and skills its .claude
  carries — to the depth its size allows, since the layout shows how the logic there is meant to work; when what that
  folder states covers what you came to do, follow it
]
