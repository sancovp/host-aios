# The session that read a body of code changes it, in its OWN worktree — a dispatched agent's change lands only in a throwaway copy

SCOPE:[binds the developer agent's own world — THE WORLD DIR, its repositories and its sessions — never a product's agents (a JobWorld seat or box, OM) or a customer's repositories, which follow their own product's design]

TRIGGER:[about to dispatch an agent — the Agent tool, a workflow's agent() — whose work touches CODE in a git repo · a lead starting an agent for one of its child projects (the `how-to-lead-an-aios` skill) · about to hand a build, a rebuild or an edit of the work's own code to an agent, to save context, in parallel or one fresh agent per piece · a dispatch that will only write WORK (documents, notes, records, boards, a project's `workspace/` outputs, by `how-to-save-work`) — it writes them in the copy in use, and the dispatching session commits them by their own paths ([[top-level-session-worktree]])]
DO:[
- change the code yourself: the session that read a body of code is the one that changes it, through the project's own system (its compiler, its abstraction library), in its own worktree off the upstream default branch ([[top-level-session-worktree]] THE TWO KINDS OF CHANGE, CODE) — so the code is read once, by the one agent that holds it, and never again by each fresh agent a build is handed to
- an agent a lead starts for one child project (the `how-to-lead-an-aios` skill) does that child's work — work, never code — in the child's copy in use, writes only that child's boards, and launches no agent of its own: the reviews and tests its work calls for are its lead's to dispatch
- dispatch an agent only to locate, to test, to review or to try something ([[00-explore-reads-everything]]), in a throwaway copy of its own off the ref: `git -C <repo> worktree add --detach <its ignored scratch folder>/worktrees/<task> <ref>` — a change it makes there is a test, never work that lands; read its output yourself, carry what it found into your own worktree, and remove its copy when done (zero dirty state)
- keep every worktree inside THE WORLD DIR, in a folder its repository ignores — a repository with no ignored scratch folder gets one by its own git loop the first time a worktree needs it · push your worktree's branch at the end of every sitting · keep no source only in an ignored file
- remove a worktree only when nothing in it would be lost ([[top-level-session-worktree]] point 12)
- STOP and rewrite a dispatch that orders a worktree on a new branch (`git worktree add … -b`), the setup for handing code to an agent; where the package's dispatch guard is installed it refuses such a dispatch before it runs, naming the reason and the remedy — a dispatch that edits the copy in use without a worktree is past its reach, and this rule binds it
]
NOT:[hand building, rebuilding or editing the work's own code to a dispatched agent · an agent started for a child project launching an agent · give a dispatched agent a branch of its own or the copy in use to change code in · make a worktree under the system's temporary folders (`/tmp`, `/private/tmp`, a session's scratchpad there) — the system deletes their files once they sit unread for days and keeps the folders, so a worktree there loses its files while git still lists it · change code in the copy in use while another agent may be live · push or merge from a dispatched agent — it lands nothing; the session that holds the code pushes it and hands it off as a ready PR, which the merge queue merges — or, while THE CI's runner starts no job, that session, which is then the CI, lands it by the queue by hand and parks nothing on *USER* ([[top-level-session-worktree]] THE GIT LOOP point 3)]
