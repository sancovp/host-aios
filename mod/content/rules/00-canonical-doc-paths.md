# THE TOPS AND THE MASTER MAP — each top AIOS's two canonical documents, and the one map naming every top

<docsys kind="canon" role="law"/>

THE TOPS:[each TOP AIOS — the canonical home ([[canonical-source-dirs]] LAW 0), and every island that home's
top-level design does not cover — has a top-level design of its own · a session finds the top that holds its work
through THE MASTER MAP, reads that top's read order, and reads no other top]
THE MASTER MAP:[a global rule in the global home's rules folder, `<global home>/rules/master-map.md` — the global home
is Claude Code's configuration folder — so Claude Code loads it into every session as a user rule, above even the AIOS
· its place is fixed, so it needs no binding · it opens with its title line, then holds one line and one link per
top-level design — what the top is, where its top-level design is — and nothing more, since every top and every folder
explains itself in full · with the global home's one line pointing down to the AIOS folder, it is all the global level
holds, and both are pointers down · the install script writes it and adds a line for each folder it installs · the map
check, the `top-level-design` skill's `check_top_level_design.py --map <the map>`, refuses a line with no link, a link
that resolves to nothing, a line over 200 characters, two lines naming one top, and any text that is not a line]
CANONICAL ANCHORS (exactly two top-level docs at the TOP of each top AIOS — a ROLE each, which the map names and the
install binds):[
1. **THE TOP-LEVEL DESIGN** — the top-down running map / LIVE STATE of what that top holds; the cover over every
   `DESIGN.md` beneath it — its line on THE MASTER MAP names it
2. **THE TOP-LEVEL STATES DOC** — that top's table of its projects, one row each, OUTSTANDING or CLEAR, linking down
   to each one's boards ([[28-distributed-state]]): redundant by construction, kept for closure, so the shape every
   level repeats closes at the top · above the tops, the global home holds no states, only the pointers down
]
THE BINDING:[THE TOP-LEVEL DESIGN and THE TOP-LEVEL STATES DOC are the map's entry for the top that holds the work —
[[user_info]]'s TOP-LEVEL DESIGN row says so · where no map loads, the installation's TOP-LEVEL DESIGN binding is its
one top, and its TOP-LEVEL STATES DOC binding that top's ledger]
LAW:[account for everything beneath a top outside its home-unknown band ([[canonical-source-dirs]] LAW 0) INSIDE one of
that top's two anchors (or a `DESIGN.md` they govern — rule 26) · in a session with no goal running, find the top
through the map and read its top-level design FIRST ([[00-top-level-design-first]]) · keep every anchor LIVE STATE —
rewritten to the current truth · cite each top by the path its map line names — or its binding, where no map loads]
MOVING A BOUND CANONICAL:[
- leave a SYMLINK at the old path, so both addresses write the same file
- freeze the pre-move copy beside it — a moved canonical keeps its archive
- rewrite its line on the map and its binding the same turn, and cite the CURRENT path, never the pre-move one
]

TRIGGER:[reading or rewriting a top-level design, a top-level states doc or THE MASTER MAP · unsure where a canonical
fact belongs (answer: inside the two anchors of the top that holds it, or a `DESIGN.md` they govern) · a new top AIOS
made — an island the canonical home's top-level design does not cover (⇒ its top-level design, and its line on the
map) · finding a reference to a canonical's pre-move path · an installation where no map loads and neither anchor is
bound (⇒ say so; the two anchors are what it owes)]
