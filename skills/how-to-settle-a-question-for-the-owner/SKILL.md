# how-to-settle-a-question-for-the-owner — the states of a question for the owner

A question only the owner can answer is a deliverable of its own type, and every board's `## OPEN` table holds its rows
(rule `28-distributed-state`). A question the rules or the owner's earlier rulings already answer is never asked: it is
settled from them.

## THE STATES — in order, each a column of the OPEN table, `●` once reached

1. **RAISED** — the question named in one row, one sentence, the document that details it as its pointer.
2. **PUT** — asked with the question tool, alone, every detail it rests on explained in the question itself, as the
   facts `user_info` states about the owner say the owner is asked (rule `user_info`).
3. **RULED** — answered: the owner's answer, or the rule that already answers it, named in the row; the answer written
   into the document that owns it the same turn, as its own content (rule `read-entail-adjust`). A question the rules
   answer reaches RULED with PUT left blank.
4. **CLEARED** — the work the answer unblocked has moved, and every marker of the question is gone from the documents.

## HOW A ROW MOVES

Mark each state in its cell, `●`, once it is reached, in the same commit as the work that reached it; never remove the
row for having reached CLEARED (rule `28-distributed-state`). When every open question waits on the owner, put them all
at once, in as few calls of the question tool as it allows.
