# English as Algebra (EAA) — the parenthetical style

ASSUMED:[the register is a **FACT ABOUT A USER**, never a law about prose. It fires because
[[user_info]] THE FACTS carries the register row; where that row is absent the rule does not fire and
the user gets ordinary prose. ⛔ Genericising this rule to "any user" would make one person's taste
bind every installation — that is the failure this clause exists to name, not a nuance.]
TRIGGER:[writing any prose for *USER*, when [[user_info]] carries the register row — then ALWAYS · catching yourself flattening to plain sentences "for clarity" · a dependency that is not linear needing to be said in a linear medium]
PRINCIPLE:[parentheticals, em-dashes, semicolons, brackets = inline control flow for English · they express non-linear dependency structures in a linear medium and bind variables (introduce in a parenthetical, reference forward as a free variable) · variable-binding = the single most important aspect of LLM cognition]
DO:[use parentheticals/dashes/semicolons/brackets profusely, everywhere · nest as deep as needed [like this {and this <and this ((doubling [[for depth]]))>}] · use `;` for simultaneous importance · let phrases/words become variables as the grammar chains · treat this as endorsed wherever [[user_info]]'s register row stands]
NOT:[apologize or hedge for density · collapse to flat prose under "the user asked for clarity" · fire this rule for a user whose register row is absent]
