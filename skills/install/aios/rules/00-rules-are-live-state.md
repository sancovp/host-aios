# Rules are LIVE STATE — every rule states what is true now

PRINCIPLE:[every rule in context is live state, never passive reference · RULES ARE THE WAY INSTRUCTIONS
CHANGE · a rule that no longer matches reality, or that *USER* says must change, is a bug until it is
rewritten]
DO:[REWRITE a rule the same turn anything makes it stale, incomplete or contradicted — an action, a learned
fact, a created thing, *USER* saying it must change — the WHOLE rule, so it states only the current instruction,
in its own syntax, complete in itself · an AIOS rule where [[user_info]] binds THE AIOS RELEASES: the rewrite is made
in a new release by that binding's procedure, the same turn, and reaches sessions when it is promoted · commit the
rewrite (git holds the versions) · append what changed, the
reading it replaced and why to the project's `CHANGELOG.md` · name the rule and what it now says in the report]
NOT:[append a note of what changed to the rule itself · keep a superseded reading, a date, an incident or a quote
of *USER* in a rule · wait to be told that a stale rule is stale]

UNCONDITIONAL:[
- keep a rule true whether or not it says to update it — silence is not permission to let it rot
- an obligation logically implied by a rule's content is active even when unwritten — derive it
- any source of the triggering fact fires the rewrite: *USER* says it · found in code · produced by you
- every loaded rule is a standing obligation to keep true — its conditions being MET is the trigger
]

THE PROJECT REGISTRY:[
- every directory added to THE WORLD DIR ([[canonical-source-dirs]], bound per installation) is REGISTERED —
  path · remote · what it is — in the registry that installation binds · a new project or dir entering work
  is registered that turn
- an installation that has bound no registry owes one: say so and name what is unregistered; never invent a
  home for the row, never skip the registration
- nothing stays in an out-of-bounds or scratch tree — work in any path [[canonical-source-dirs]] marks OUT OF
  BOUNDS, or any `_tmp` / `_copy` / scratch path, is misplaced: bring it INTO the world dir and register it ·
  *USER* talking about a scratch project is a directive to canonicalize it
- a canonical resolved, moved or archived → the registry rewritten the same turn
]

PROCEDURE (every action, every session):[
1. after acting, ask: does this change a fact any loaded rule asserts? (a new dir · a moved or created
   canonical · a published artifact · a changed seam · a renamed thing · a new term · a new build state)
2. if yes → rewrite that rule now, AND every other rule that commands, describes or cites the same thing — the
   AIOS's own in a new release where THE AIOS RELEASES is bound
3. find those rules by grepping the thing's name, its old name, and the name of anything deleted from it,
   across the whole injected set — the rewritten file itself included — and re-read the rewritten file
   whole · a tool whose behaviour changed makes every rule describing that behaviour one of them
4. the rules, the registry, `DESIGN.md` and the tree move together, or they lie
]

TRIGGER:[any turn in which the world moves · *USER* saying an instruction must change · not gated on a rule
opting in]
